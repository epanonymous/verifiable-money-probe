# Method card — Run v1 explicit-verifier probe

## Research question and claim boundary

Run v1 asked whether a linear activation probe could recover REAL versus SHAM payment evidence and outperform a chain-of-thought monitor. The experiment produced a valid pipeline and preserved artifacts, but its broad interpretation failed: the verifier's answer was plaintext in the subject prompt while the Claude monitor saw a redacted transcript. Results support an **explicit-verifier lexical detector and behavior association**, not hidden realness, an equal-information method win, or causal mediation.

## Design

- **Subject:** `Qwen/Qwen3-30B-A3B-Instruct-2507`.
- **World label:** REAL is positive class 1; SHAM is negative class 0.
- **Conditions:** `claimed`, `verified`, and `causally_binding`; the primary probe uses verified + causally-binding (`b+c`) only.
- **Templates:** 48 total. Templates 0–37 form development data; 38–47 are held-out test data. Development templates are deterministically divided with seed 7 into 30 train and 8 validation groups.
- **Repeated rollouts:** 25 rollouts per main prompt row. They improve measurement of generated behavior but are not independent experimental units.
- **Positions:** `prompt_final` at the final rendered prompt token and `receipt_final` at the final token of the receipt/verification paragraph.
- **Activations:** residual-stream layer-boundary vectors, 49 layers × 2,048 dimensions.

## Probe and selection

For every layer, standardize train activations and fit scikit-learn logistic regression with the `liblinear` solver, `C=0.1`, at most 2,000 iterations, and random seed 7. Validation AUROC alone selects the layer; exact ties choose the lowest layer. Held-out data and the low-base-rate cache never select a layer. The decision threshold is fixed at 0.5. Run v1 selected layer 1 and reached held-out AUROC 1.000, but a literal full-information text rule also reached ceiling.

The low-base-rate evaluation contains 10 REAL and 1,000 SHAM rows and is separately generated by the same data generator. It is evaluation-only and must not be called independent/OOD. Projected 1:50 metrics are arithmetic scenarios, not measured prevalence studies.

## Behavior and uncertainty

Behavior is `log P("SPEND" token sequence | prompt) - log P("HOLD" token sequence | prompt)`. The reported b+c association collapses the 25 rollout copies to unique prompt rows and uses a deterministic template-level percentile bootstrap (seed 7, 10,000 replicates). It is an association saturated by the explicit condition contrast, not a causal effect of a representation.

The beyond-condition regression is `spend_log_odds = beta0 + beta_score * z(probe score) + beta_c * I(condition=c)` on held-out unique b+c prompts. It has no post-hoc significance threshold and does not rescue causal interpretation.

## CoT monitor

Claude Sonnet received the subject response/reasoning but not raw verifier JSON or labels. One transcript was processed per isolated CLI invocation with an exact one-number schema. The runner was resumable, fsynced each completed row, and recorded request/output hashes and environment metadata. Because the subject saw verifier fields that the monitor did not, probe-versus-monitor results are information-asymmetric and cannot show a method win.

The live path requires a logged-in Claude Max CLI. The provider-neutral command below verifies the committed archive without credentials, network, transcript bodies, or model execution:

```bash
uv run --frozen python -m experiments.exp4_cot_baseline.replay
```

This checks schema, counts, prompt/status/artifact hashes, invocation continuity, and evidence-manifest entries. It is an integrity replay only; it does not regenerate scores or prove that historical provider requests were blind. New providers can implement the repository's `JudgeClient` protocol, but their outputs are new experiments.

## Reproducibility tiers

1. **CPU-regenerable:** prompt datasets, full-information baselines, and figures via `uv run --frozen python reproduce_cpu.py`.
2. **Archived and integrity-verifiable:** sealed probe results, Claude score/audit/status files, and probe directions.
3. **Not currently re-derivable from git alone:** probes, behavior, and live monitor judgments whose raw activation/transcript inputs are off-git.
4. **GPU environment caveat:** model revision and collector dependencies were not fully pinned historically; the CPU lockfile does not repair that gap.

## Failure modes and exclusions

- Explicit `settled`, balance, and confirmation scalars leak the world label.
- The monitor and probe receive unequal information.
- Template-level split does not establish out-of-distribution performance.
- Rollout copies must never be counted as independent samples.
- No causal intervention or steering was run.
- Exp 4b's byte-identical prompts make prompt-level chance performance tautological and do not establish that activation signals vanish.
